- Severity: major
  File: lib/bless_this_redmine_sso/hooks.rb:22-27
  Problem: Unescaped HTML is interpolated into the login button. The input value attribute uses login_text directly in a raw HTML string; if the configured provider name contains quotes or HTML, it will break the attribute and inject markup/JS into the login page. This string is shown to every unauthenticated user.
  Failure scenario: An admin (or an attacker who can change settings) sets OAuth provider name to '"><img src=x onerror=alert(1)>' in the plugin settings. Visiting /login renders:
    <input type="submit" value="Login with "><img src=x onerror=alert(1)>" id="oauth-login-submit" />
  which executes onerror.
  Fix: Escape the text before inserting into HTML. Preferably build the button with Rails helpers so attributes are escaped:
    - Replace the heredoc with helpers, e.g. submit_tag(ERB::Util.h(login_text), id: 'oauth-login-submit') inside a form_tag(oauth_authorize_path, method: :get).
    - At minimum, wrap login_text in ERB::Util.h before interpolation.
  Resolution: not a defect. The provider name goes through h() before it is put into the label (`provider: h(provider_name)`), so the attribute cannot be broken; the shipped translations contain no quotes. New spec 'escapes the provider name in the button' (spec/lib/hooks_spec.rb) renders exactly the given payload and passes. Only admins can set the name.

- Severity: major
  File: lib/bless_this_redmine_sso/hooks.rb:23 and lib/bless_this_redmine_sso/patches/account_controller_patch.rb:28
  Problem: Hard-coded path /oauth/sso/authorize ignores Redmine’s relative_url_root. On deployments mounted under a sub-URI (e.g. /redmine), the SSO form and redirect will point to a non-existent top-level path and fail.
  Failure scenario: Redmine served at https://host/redmine. The login page form posts to /oauth/sso/authorize; the request 404s because the correct path is /redmine/oauth/sso/authorize. Likewise, GET /logout redirect builds a URL starting at /oauth/sso/authorize and fails.
  Fix: Use route helpers that honor the mount point:
    - Name the route in config/routes.rb (e.g. get '/oauth/sso/authorize', to: 'oauth#authorize', as: :oauth_sso_authorize).
    - In hooks.rb, set the form action to oauth_sso_authorize_path or url_for(controller: 'oauth', action: 'authorize').
    - In account_controller_patch.rb, build the URL with oauth_sso_authorize_path plus query, not a hard-coded string.
  Resolution: valid but pre-existing and not caused by Redmine 7 (the same paths existed on 5.1, and the callback default also uses request.base_url + '/oauth/callback'); GEOxyz runs Redmine at the root. Not fixed in the migration, recorded under 'Findings not fixed' in docs/REDMINE7-MIGRATION.md.

- Severity: major
  File: app/controllers/oauth_controller.rb:156-164
  Problem: The callback error branch uses params[:error] unconditionally to populate flash[:error], even when no OAuth flow was started (no state in session). Because flash is stored in the session cookie, a large error parameter on a public endpoint can bloat the cookie and trigger “Header too large”/Cookie overflow responses (DoS), and it unnecessarily reflects attacker-controlled text back to the user (now escaped, but still unbounded).
  Failure scenario: An unauthenticated GET to /oauth/callback?error=<1MB_of_text> causes the app to try to store that text in flash and send it back, breaking the response with a 400/502 due to header size limits and clearing the user’s session.
  Fix: Only include provider-supplied error text when an OAuth flow is in progress (e.g. session[:oauth_state].present?). Otherwise, show a generic message. Also cap the length:
    error_msg = if session[:oauth_state].present? && params[:error].present?
                   params[:error].to_s.first(200)
                 else
                   l(:flash_unknown_error, scope: :bless_this_redmine_sso)
                 end
    flash[:error] = l(:flash_oauth_failed, scope: :bless_this_redmine_sso, error: ERB::Util.h(error_msg))
  Resolution: does not reproduce: the error branch is only reached after the state check (`state == session[:oauth_state]`), so without a flow started in that browser the parameter is never read and the flash is the fixed 'invalid state' text. Pinned by the new spec 'ignores the error parameter when no OAuth flow is in progress' (5000-char error, flash does not contain it) and the e2e forged-state screenshot. An attacker can only bloat their own session.

  Problem: The “is the same statement in every shipped locale” test can pass even if a locale is missing the key, because Redmine/I18n can fall back to English. The test then sees identical strings and reports success, masking a missing translation.
  Failure scenario: Remove warning_sso_only_db_command from, e.g., it.yml. I18n falls back to en, statements.uniq.size remains 1, test passes, but the UI would show English instead of Italian at runtime.

    %w[en nl de fr es it pt].each do |l|

    end
    statements = %w[...].map { |l| I18n.t(:warning_sso_only_db_command, scope: :bless_this_redmine_sso, locale: l, raise: true) }
    expect(statements.uniq.size).to eq(1)
  Resolution: fixed in the next commit: I18n.t(..., raise: true, fallback: false); verified that removing the key from it.yml now fails the spec.
