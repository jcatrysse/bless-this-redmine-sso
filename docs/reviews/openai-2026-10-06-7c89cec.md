- Severity: blocker
  File: app/controllers/oauth_controller.rb:26 and 57
  Problem: Local variable shadowing of params breaks reading controller parameters. The method computes prompt_login as `session.delete(:oauth_prompt_login) || params[:prompt] == 'login'` and later assigns `params = { ... }` for the authorize query. In Ruby, any assignment to a local variable causes all references in the method to refer to that local variable. Here, the earlier `params[:prompt]` is treated as the uninitialized local variable (nil), causing `NoMethodError: undefined method '[]' for nil:NilClass`.
  Failure scenario: Visiting /oauth/sso/authorize with no oauth_prompt_login flag set (the common case) triggers evaluation of the right side of `||`, raising at `params[:prompt]`. This breaks the SSO flow before redirecting to the provider.
  Fix: Do not use the name params for the local query hash. For example:
    - Read controller params explicitly as `self.params[:prompt] == 'login'`, and
    - Rename the local hash to auth_params:
      `auth_params = { client_id: ..., state: state }`
      `auth_params[:prompt] = 'login' if prompt_login`
      and use auth_params to build the redirect URL.
  Resolution: does not reproduce. A Ruby local variable exists only from its assignment onward in the source; `params[:prompt]` on line 26 comes before `params = {...}` and calls the controller method. Shown in isolation (`ruby -e` with the same shape returns [true, {x: 1, prompt: "login"}]), by the specs 'forwards prompt=login from the SSO-only login redirect' and 'redirects to the provider without PKCE params' (51/51 green), and by every e2e SSO login on PostgreSQL and MariaDB. The local name `params` predates this branch; renaming it would be a drive-by refactoring.

  File: lib/bless_this_redmine_sso/hooks.rb:25; lib/bless_this_redmine_sso/patches/account_controller_patch.rb:31
  Problem: Hard-coded absolute paths ignore relative_url_root. The login form action is a literal "/oauth/sso/authorize", and AccountControllerPatch builds a URL string starting with "/oauth/sso/authorize". On Redmine instances deployed under a sub-URI, these links will point to the wrong location.
  Failure scenario: Redmine is served at https://host/redmine (relative_url_root = "/redmine"). The login button posts to https://host/oauth/sso/authorize instead of https://host/redmine/oauth/sso/authorize, resulting in a 404 and making SSO unusable.
  Fix: Generate paths via helpers that respect the relative_url_root, or prefix with it:
    - In the hook, build the form action with `Redmine::Utils.relative_url_root + oauth_sso_path` or `main_app.url_for(controller: 'oauth', action: 'authorize', only_path: true)` (define a named route if needed).
    - In AccountControllerPatch, build `url = "#{Redmine::Utils.relative_url_root}/oauth/sso/authorize"` and append the query string, or use the same url_for helper.
